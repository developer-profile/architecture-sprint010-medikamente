# Анализ безопасности информационной системы

## I. Идентификация конфиденциальных данных в корпоративной инфраструктуре

Организация осуществляет обработку следующих категорий конфиденциальной информации, подлежащей защите в соответствии с требованиями ФЗ-152 "О персональных данных" и отраслевыми стандартами безопасности:

I. Персональные идентификационные данные (PII):
   i. ФИО, дата рождения, контактные данные (телефон, email)
   ii. Адрес регистрации, сведения о месте трудовой деятельности/обучения

II. Медицинская информация:
   i. Клинические диагнозы, результаты лабораторных исследований, электронные медицинские карты (форматы PDF/JPG)
   ii. Данные о хронических патологиях, анамнестическая информация

III. Финансовые данные:
   i. Платежные реквизиты (обрабатываемые через ККМ и систему 1С)
   ii. Договорная документация по оказанию медицинских услуг

IV. Учетные данные персонала:
   i. Аутентификационная информация (логины/пароли в Active Directory)
   ii. Данные для ведения кадрового и зарплатного учета (1С:Бухгалтерия)

Анализ процессов и выявленные уязвимости:

I. Процесс регистрации пациентов на медицинские консультации:
   i. Отсутствие механизмов ролевого разграничения доступа (RBAC) в Excel-документах
   ii. Передача данных без применения криптографической защиты

II. Процесс обработки медицинской информации:
   i. Отсутствие логического разделения медицинских и финансовых данных
   ii. Отсутствие системы контроля версий файловых ресурсов

III. Процесс учета товарно-материальных ценностей:
   i. Неконтролируемый доступ к данным ТМЦ (отсутствие ролей "Складской учет"/"Бухгалтерский учет")

## II. Аудит существующих мер информационной безопасности

Выявленные недостатки текущей системы защиты информации:

I. Хранение данных в неструктурированном формате (Excel, сканированные документы) без реализации механизмов разграничения доступа
II. Отсутствие системы аудита операций с конфиденциальными данными
III. Незащищенные интеграционные каналы между информационными системами (1С, Excel, файловый сервер)

## III. Рекомендации по совершенствованию системы защиты информации

### Категоризация данных:

I. Выделение доменных областей: PII, Medical, Financial, HR
II. Определение RBAC-ролей для каждого домена (например, роль "Врач" → доступ исключительно к данным закрепленных пациентов)

### Технологические решения:

I. Замещение Excel-документов реляционной СУБД (PostgreSQL для структурированных данных, MinIO для файлового хранения)
II. Внедрение системы управления секретами Vault для API-ключей лабораторных интеграций

### Меры информационной безопасности:

I. Криптографическая защита данных в состоянии покоя и передачи (протоколы TLS, PGP)
II. Внедрение системы предотвращения утечек данных (DLP) для мониторинга несанкционированного доступа

### Интеграционная архитектура:

I. Развертывание API-шлюза (Kong) для контроля доступа к лабораторным системам
II. Реализация централизованного аудита и логирования (Elasticsearch + SIEM)

### Технические требования:

I. Маскирование персональных данных в API-интерфейсах (замещение ФИО на уникальные идентификаторы)
II. Ведение журнала аудита для всех API-запросов

## Заключение

Существующая система хранения и обработки данных не соответствует требованиям информационной безопасности. Необходимо внедрение централизованного хранилища данных с реализацией контроля доступа, системы аудита и криптографической защиты. Приоритетным направлением является миграция с Excel-документов на реляционную СУБД и настройка механизмов ролевого разграничения доступа.
